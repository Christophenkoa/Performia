# Performia on NestJS - Design

Date: 2026-10-04
Status: Approved in chat, pending spec review

## Goal

Rebuild helloperformia.com (currently a client-rendered React app generated by Hostinger Horizons) as a server-rendered NestJS application that we fully own. The new app keeps the existing content, structure, bilingual support and visual style, and adds a real, secured contact endpoint.

Success criteria:

- `/`, `/contact`, `/en`, `/en/contact` render complete HTML on the server (content visible with JavaScript disabled).
- All copy from the current site (FR and EN) is present and lives in one place per language.
- The contact form validates input server-side, resists basic spam, and works without JavaScript.
- No runtime dependency on Hostinger (scripts, CDN) or Unsplash.
- `npm run build`, `npm test` and `npm run test:e2e` pass.

## Source analysis

- Source: `https://helloperformia.com`, bundle `assets/index-DtYdwJnH.js`, styles `assets/index-CR_jwmoD.css`.
- Routes: `/` (home) and `/contact`.
- Languages: French (default) and English, switched client-side in the original.
- Contact form in the original has no backend call.
- External assets: logo on `horizons-cdn.hostinger.com`, hero image from `images.unsplash.com/photo-1687600154336-71d3d1a5701c`.

## Architecture

Single NestJS app (TypeScript, Node 24, npm), Handlebars views via `@nestjs/platform-express` + `hbs`, Tailwind CSS compiled at build time.

```
src/
  main.ts                 bootstrap: helmet, views, static assets, cookie parser, CSRF
  app.module.ts
  content/
    content.module.ts
    content.service.ts    getContent(lang): SiteContent
    content.types.ts      SiteContent interface (single source of truth for shape)
    fr.ts                 French copy
    en.ts                 English copy
  pages/
    pages.module.ts
    pages.controller.ts   GET /, /contact, /en, /en/contact
  contact/
    contact.module.ts
    contact.controller.ts POST /contact, POST /en/contact
    contact.dto.ts        class-validator DTO
    contact-notifier.ts   ContactNotifier interface + LoggingContactNotifier
views/
  layouts/main.hbs
  partials/               header, footer, one partial per home section
  home.hbs
  contact.hbs
public/
  css/app.css             Tailwind build output (gitignored)
  img/                    logo, hero image (downloaded once, served locally)
styles/tailwind.css       Tailwind input
test/                     e2e tests
```

### Units

- **ContentModule**: returns a typed `SiteContent` object for `fr` or `en`. Both files must satisfy the same interface so a missing translation is a compile error. Values that look like placeholders carry a `// TODO: verify` comment.
- **PagesModule**: maps a URL to a language and view, passes `content`, `lang`, `alternateUrl` and the CSRF token to the template. No business logic.
- **ContactModule**: validates the DTO, checks the honeypot, calls `ContactNotifier.notify()`, then redirects (PRG pattern). Depends only on the `ContactNotifier` token, so email delivery can replace logging later without touching the controller.

### Routing and i18n

- French at `/` and `/contact`, English at `/en` and `/en/contact`.
- Header switcher links to the equivalent page in the other language.
- `<html lang>`, `<link rel="alternate" hreflang>` for both languages, per-language `<title>` and meta description.

## Contact flow

1. Browser submits `POST /contact` (or `/en/contact`) as a normal form post with a CSRF token.
2. `ContactDto` validation (class-validator, whitelist + forbidNonWhitelisted):
   - `name`: string, 2-100 chars, trimmed
   - `email`: valid email, max 254 chars
   - `phone`: optional, max 30 chars, digits, spaces, `+`, `-`, `()`
   - `message`: string, 10-2000 chars
   - `website`: honeypot, must be empty
3. Honeypot filled: respond with the same success redirect but do not notify (silent drop).
4. Validation errors: re-render the contact view with status 400, localized error messages and the submitted values.
5. Valid: `ContactNotifier.notify(request)` (v1 logs a structured line without the message body to limit personal data in logs), then `303` redirect to `/contact?sent=1`, which shows a success notice.
6. Rate limit: `@nestjs/throttler`, 5 requests per minute per IP on the contact routes; excess returns 429.

## Security

- `helmet` with a strict CSP: `default-src 'self'`, no inline scripts, images from `'self'` only.
- Handlebars auto-escaping for all content; no triple-stash on user input.
- CSRF protection on the form (double-submit cookie via `csrf-csrf`).
- Body size limit 10 kb for form posts.
- Config via `@nestjs/config`; `.env.example` committed, `.env` gitignored. v1 needs only `PORT` and `CSRF_SECRET`.
- GDPR: logs contain name and email only for the contact event; message text is not logged. A privacy notice line under the form states how the data is used.

## Testing

- Unit: `ContactDto` validation cases (valid, each invalid field), honeypot handling in the controller, `ContentService` returns both languages.
- E2E (supertest): `GET /`, `/en`, `/contact`, `/en/contact` return 200 and contain a known heading per language; security headers present; valid POST with CSRF token returns 303; invalid POST returns 400 with errors; POST without CSRF token is rejected; sixth POST in a minute returns 429.

## Out of scope (v1)

- Email or database delivery of contact requests (interface prepared).
- CMS or admin UI for content.
- Analytics, cookie banner, deployment pipeline.

## Assumptions and open points

1. Placeholder-looking data is copied unchanged and marked `// TODO: verify`: WhatsApp `+225 07 07 12 34 56`, generic Facebook/Instagram URLs, "847 familles", "92% de nos élèves améliorent leurs notes en moins de 3 mois", the three testimonials, and the refund guarantee. Public figures and testimonials need to be verified against a real source before launch.
2. Hostinger Horizons runtime scripts (postMessage error relay, fetch interception, navigation guard) are dropped; they only serve the Horizons editor.
3. The logo and hero image are downloaded once and committed. The Unsplash image license allows this; the logo is the client's own asset.
